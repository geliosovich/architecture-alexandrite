# Архитектурное решение по логированию: детализация и пояснения

## 1. Объекты логирования и их назначение

Логирование будет охватывать ключевые компоненты системы для обеспечения прозрачности работы и быстрого реагирования на проблемы:

- **Internet Shop (Shop API)**  
  Фиксирует действия клиентов, запросы к БД и обработку заказов.
- **CRM (CRM API)**  
  Логирует управление заказами, обновления статусов и взаимодействия с продавцами.
- **MES (MES API)**  
  Записывает операции, связанные с производством и упаковкой.
- **RabbitMQ (Message Queue)**  
  Отслеживает передачу сообщений между CRM и MES.
- **Базы данных (Shop DB, MES DB)**  
  Логирует ошибки транзакций и задержки запросов.
- **3D File Storage (S3)**  
  Фиксирует операции загрузки, скачивания и ошибки работы с файлами.

## 2. Уровни логирования и примеры событий

### Уровень INFO (информационные события)
- **Internet Shop**: создание/обновление заказов, авторизация пользователей.
- **CRM**: подтверждение заказов, изменение статусов, взаимодействие с RabbitMQ.
- **MES**: взятие заказов в работу, завершение производства, отправка.
- **RabbitMQ**: публикация и подтверждение обработки сообщений.
- **Базы данных**: запросы к БД, ошибки соединений.
- **S3**: загрузка файлов, ошибки доступа.

### Уровень ERROR (критические ошибки)
- Ошибки БД, приводящие к потере данных.
- Сбои при отправке сообщений в RabbitMQ.
- Проблемы взаимодействия с MES API.
- Ошибки загрузки файлов в S3.

### Уровень WARNING (потенциальные проблемы)
- Долгие ответы API.
- Попытки загрузки слишком больших файлов в S3.

## 3. Мотивация и преимущества

Логирование решает следующие задачи:
- **Технические**:
    - Сокращение времени обнаружения и исправления ошибок.
    - Мониторинг процента неудачных запросов API.
    - Контроль времени ответа БД.
- **Бизнес-метрики**:
    - Уменьшение просроченных заказов и жалоб клиентов.
    - Повышение скорости обработки заказов.

Ключевые системы (Internet Shop, CRM, MES) логируются в приоритетном порядке, так как они связаны с основными бизнес-процессами.

## 4. Реализация с использованием ELK-стека

### Компоненты решения:
- **Elasticsearch**: хранение и индексация логов.
- **Logstash**: фильтрация и агрегация данных.
- **Kibana**: визуализация и поиск.

### Доработки для интеграции:
- API (Shop, CRM, MES) отправляют логи через **Filebeat/Logstash**.
- RabbitMQ и БД логируют события напрямую.
- S3 использует **S3 Access Logs**.

## 5. Политики безопасности и хранения

### Безопасность:
- Логи хранятся в закрытом контуре сети.
- Доступ ограничен для DevOps и администраторов.
- Чувствительные данные маскируются в **Logstash**.

### Хранение:
- Данные каждого сервиса хранятся в **отдельных индексах** Elasticsearch.
- Ротация логов: удаление через **30 дней**.
- Ограничение размера индекса (**50 ГБ**).

## 6. Алертинг и поиск аномалий

### Критические алерты:
- Ошибки БД, API, RabbitMQ, S3.
- Задержки ответа API или обработки заказов в MES.

### Поиск аномалий:
- Резкий рост запросов на создание заказов (возможная DDoS-атака).
- Увеличение ошибок авторизации (автоматизированные атаки).
- Аномальное количество отказов API (проблемы интеграций).

Для автоматизации анализа аномалий в будущем планируется внедрение инструментов **ИИ**.

## 7. Итог

Предложенное решение обеспечит:
- Надежное логирование ключевых событий.
- Быстрое реагирование на инциденты.
- Улучшение технических и бизнес-метрик.
- Гибкость и масштабируемость за счет ELK-стека.
