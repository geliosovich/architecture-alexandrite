# Мотивация
Внедрение системы мониторинга и оповещений имеет критическое значение для повышения эффективности работы системы. Это позволяет выявлять проблемные места, анализировать причины задержек в обработке заказов и оценивать необходимость масштабирования.
Мониторинг способствует повышению стабильности и предсказуемости работы системы, что снижает риски внезапных сбоев. Анализ метрик помогает заранее обнаруживать потенциальные проблемы и устранять их до того, как они повлияют на клиентов.
Кроме того, система мониторинга улучшает качество пользовательского опыта. Контроль за задержками в обработке заказов и API-запросов позволяет сократить время выполнения операций, что увеличивает удовлетворённость клиентов, уменьшает количество жалоб и повышает их лояльность.
В итоге внедрение мониторинга и оповещений не только помогает предотвращать потери прибыли, но и позволяет эффективно реагировать на возрастающий спрос, оптимизировать работу системы и, как следствие, повышать доход компании.

# Выбор подхода к мониторингу
Выбор конкретного подхода зависит от задач, стоящих перед командой, и особенностей архитектуры системы.

## Подход USE
Так как подход USE позволяет систематически оценивать состояние системы, выявлять потенциальные проблемы и принимать меры по их устранению. Он помогает обеспечить более эффективное использование ресурсов, предотвратить сбои и улучшить общую производительность системы. Логи, собранные на основе этих параметров, могут быть использованы для дальнейшего анализа, оптимизации и планирования развития инфраструктуры. Она отлично подходит для оценки баз данных (Shop DB, MES DB), хранилище файлов(S3) и очереди сообщений (RabbitMQ). 

## Подходы RED
Подход RED позволяет систематически оценивать ключевые показатели производительности системы, быстро выявлять и устранять проблемы, а также оптимизировать работу системы для обеспечения высокой производительности и надёжности. Этот подход отлично подходит для CRM API и MES API. Логи, собранные на основе этих параметров, могут быть использованы для дальнейшего анализа и улучшения работы системы.

## Подход Четыре золотых сигнала
Этот подход в мониторинге и анализе производительности систем, помогает оценить состояние и стабильность работы сервисов. Компоненты CRM, MES, Internet Shop как раз нуждаются в периодической оценке как количественных так и качественных показателей, на основе которы можно оценить удобство работы с системой. Частые ошибки и/или долгий отклик системы отрицательно сказываются на удобстве.

# Метрики состояния системы
## RabbitMQ, БД, S3
 - Все: CPU, MEM, Дисковое пространство
 - RabbitMQ: Размер очередей (количество сообщений в очереди), количество активных соединений, количество открытых каналов, время обработки сообщений, пропускная способность, задержки в доставке сообщений.
 - S3: Объём использованного хранилища, количество объектов, пропускная способность, задержки
 - БД: Время отклика, пропускная способность, задержки, количество транзакций в секунду

## CRM API,MES API и Shop API 
 - Время отклика
 - Коды состояния HTTP 
 - Количество ошибок
 - задержки
 - число активных соединений
 - размер ответа
 - частота запросов 

## CRM, MES, Internet Shop
 - Время отклика интерфейса на действия пользователя (например, открытие страницы клиента, поиск по базе данных).
 - Время обработки запросов к серверу (например, сохранение изменений в профиле клиента, отправка писем через интеграцию с электронной почтой).
 - Время загрузки страниц и отчётов в CRM.

### Traffic (Трафик)
  - Количество запросов к CRM-системе за определённый период времени (например, количество входов в систему, количество обращений к базе данных клиентов).
  - Частота использования различных функций CRM (например, сколько раз были созданы новые сделки, сколько раз обновлены данные клиентов).
  - Объём данных, передаваемых между клиентом и сервером (например, объём данных, загружаемых при открытии отчётов).

### Errors (Ошибки)
  - Количество ошибок при выполнении запросов к CRM (например, ошибки при сохранении данных, ошибки аутентификации).
  - Частота сбоев в работе интеграций с другими системами (например, сбои при синхронизации данных с учётной системой).
  - Количество жалоб от пользователей на некорректную работу CRM.

### Saturation (Насыщенность)
  - Использование ресурсов сервера, на котором работает CRM (например, загрузка CPU, использование оперативной памяти, дискового пространства).
  - Количество одновременных подключений к CRM-системе.
  - Уровень использования лицензий и лимитов, установленных для пользователей (например, количество созданных сделок на пользователя, объём хранимых данных).3

# Бизнес метрики
## Internet Shop
  - В разрезе пользователей - контроль количества активных пользователей, анализ динамики роста клиентов магазина.
  - В разрезе количества заказов - отслеживание общего количества заказов, выявление трендов и сезонных колебаний.
  - В разрезе статусов - анализ статусов заказов, выявление задержек и узких мест в обработке.
