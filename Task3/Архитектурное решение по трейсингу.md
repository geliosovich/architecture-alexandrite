# Архитектурное решение по трейсингу

## 1. Области применения трейсинга
Ключевые компоненты для внедрения:
- **Обработка заказов**:
    - Приём заказов от клиентов интернет-магазина + загрузка 3D-моделей
    - Приём заказов от продавцов через CRM
    - Прямой API-приём заказов
- **Производство**:
    - Обработка и выполнение заказов в MES

## 2. Критические точки системы
| Компонент                     | Потенциальные проблемы                 |
|-------------------------------|----------------------------------------|
| Shop API → Shop DB            | Ошибки создания/записи заказов         |
| Shop API → File Storage       | Сбои загрузки 3D-моделей               |
| CRM API ↔ RabbitMQ ↔ MES API  | Потеря/зависание статусных сообщений   |
| MES API → MES DB              | Проблемы обработки на производстве     |

## 3. Данные для трейсинга
- **Идентификаторы**:
    - Order ID
    - RabbitMQ Message ID
- **Метрики**:
    - Время обработки на этапах
    - Размеры файлов 3D-моделей
- **Диагностика**:
    - Статусы заказов
    - Ошибки API/БД

## 4. Мотивация внедрения
Трейсинг позволит: 
- Выявлять узкие места: Определять, где происходят задержки или сбои.
- Улучшить метрики:
  - Технические: Среднее время обработки заказа, время ответа API, частота ошибок.
  - Бизнес-метрики: Снижение просроченных заказов, уменьшение жалоб клиентов, рост производительности.

## 5. Техническое решение
Для сбора и анализа данных будет использоваться стек OpenTelemetry + Jaeger:
 - Сбор данных:
    - Интеграция otel-sdk в Shop API, CRM API, MES API. 
    - Проксирование запросов к MES и S3 через sidecar (nginx + otel-sdk).
    - Мониторинг RabbitMQ с помощью otel-rabbitmq.

 - Хранение и анализ:
    - Трассировки хранятся в Jaeger + Elasticsearch.
    - Визуализация через Jaeger UI и Grafana.

## 6. Потенциальные проблемы и риски при внедрении (компромиссы)
Проприетарные системы: Для MES и S3 потребуются обходные решения (прокси), что может увеличить задержки.
Ресурсоемкость: Внедрение в устаревший код требует значительных трудозатрат.
Стоимость хранения: Увеличение трафика приведет к росту затрат на хранение данных в Elasticsearch.
Безопасность: Доступ к Jaeger и Grafana ограничен ролями (например, "Поддержка"). Ведется аудит действий пользователей.

## 7. Особенности внедрения
Тестирование: Перед полным внедрением протестировать трейсинг на отдельных компонентах.
Масштабирование: Заранее оценить нагрузку на Elasticsearch и Jaeger для больших объемов данных.
Документация: Подготовить руководства для команды поддержки по работе с Jaeger и Grafana.

Это решение обеспечит прозрачность работы системы, ускорит выявление и устранение проблем, а также улучшит взаимодействие между модулями.
